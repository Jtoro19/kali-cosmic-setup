# kitty

## Purpose

Install and configure the kitty terminal (frosted glass, cursor trail, smooth
scrolling), keep its selection colour in sync with the COSMIC accent colour, add
a `clear` alias that also wipes scrollback, and make kitty the default terminal
in COSMIC (Super+T). `MODULE_OPTIN=0`, no dependencies.

## Source of truth

eos `40-kitty.sh`, `specs/kitty.md` and `files/kitty/*`, ported to apt with the
fixes found in `odd/verified-facts.md` (sections 1 and 7: theme keys are
version 2 and `system_actions` is a whole map). Payload in `files/kitty/`:
`kitty.conf` (unchanged), `kitty-cosmic-colors.sh` (rewritten for theme v2),
the `.service` (unchanged) and the `.path` (v2 paths). `cosmic-colors.conf` is
generated and not shipped. kitty 0.48.2 from Kali (the config needs 0.46+).

## Files and packages touched

- Package: `kitty` (Kali).
- `~/.config/kitty/kitty.conf` (0644), `~/.local/bin/kitty-cosmic-colors.sh`
  (0755), `~/.config/systemd/user/kitty-cosmic-colors.service` and `.path`.
- `~/.config/kitty/cosmic-colors.conf`: generated by the script (the module runs
  it when the script or a unit changed, or the file is missing).
- Unit enabled and started: `kitty-cosmic-colors.path` (user).
- The rc file of the login shell, a managed block `kitty-clear` with
  `alias clear='printf "\e[H\e[2J\e[3J"'`: `~/.zshrc` for a zsh login shell,
  `~/.bashrc` for bash. The legacy unmanaged alias (and its old Spanish comment)
  is removed from that file.
- `~/.config/cosmic/com.system76.CosmicSettings.Shortcuts/v1/system_actions`.
- `~/.config/cosmic-mimeapps.list`: `x-scheme-handler/terminal` and
  `application/x-terminal-emulator` = `kitty.desktop` under `[Default Applications]`.

## Decisions on ambiguities

1. **Colour sync reads theme version 2 (eos bug fixed).** eos read
   `CosmicTheme.<Dark|Light>/v1/accent` and parsed float `red:/green:/blue:`
   channels. COSMIC 1.11 writes version 2 (hex strings, `base: "#63D0DFFF"`);
   `v1` is a legacy copy that is not updated, so the eos script never saw theme
   changes. The script now takes the first `base: "#RRGGBBAA"` of
   `CosmicTheme.<T>/v2/accent` (no float maths; the alpha byte is dropped),
   `T` from `CosmicTheme.Mode/v1/is_dark` (literal `true`/`false`; only v1
   exists for Mode). The selection text is black above a luminance of 0.6
   (integer maths on the hex bytes, `sh`/dash compatible). With no user file yet
   (a fresh account) the shipped `/usr/share/cosmic/.../v2/accent` is read. The
   path unit watches `Dark/v2/accent`, `Light/v2/accent` and `Mode/v1/is_dark`.
   A v1 file is never read. A v2 file without a hex `base` exits 1 with a message.
2. **`system_actions` is the whole map.** In COSMIC 1.11 the user key replaces the
   shipped map (verified: `/usr/share/cosmic/.../v1/system_actions` is a full RON
   map of 25 actions), so eos's one-entry file would drop every other action. The
   module copies the shipped map (comments and all) with only
   `Terminal: "cosmic-term"` changed to `Terminal: "kitty"`. An existing user file
   keeps all its entries: only a Terminal command that is still `cosmic-term` is
   switched; any other terminal the user chose (or no Terminal entry) is kept with
   a warning. If the shipped map cannot be read no partial map is written. A file
   owned by another user is never written (no sudo for user config).
   `cosmic-comp` reads this key (the string `system_actions` is in the binary).
3. **Default terminal for apps.** `cosmic-settings` and `cosmic-files` mention
   `x-scheme-handler/terminal` (verified with `grep -ac`), so the
   `cosmic-mimeapps.list` lines from eos stay. A handler the user already set is
   kept (the helper warns). A new file is written in one step.
4. **Shell block by login shell.** `login_rc_file` (lib/common.sh) reads the login
   shell from `getent passwd`, not from `$SHELL`: zsh gives `~/.zshrc`, bash
   `~/.bashrc`; any other shell (fish, dash, ...) gets a warning and no block. The
   shell is never changed. The alias syntax is valid in both shells.
5. **No user manager (SSH without a session).** The files are written and the
   colours are generated; enabling the path unit is skipped with a warning that
   names the command to run after logging in.
6. Background blur depends on the compositor (harmless if ignored).

## Hardware detection

None (kitty needs OpenGL; the VM has virtio 3D acceleration).

## Idempotency check

Files are compared byte by byte; the shell block, INI lines and the Terminal
command are checked before writing; the path unit is enabled only when not
enabled; the script runs only when it or a unit changed (or the generated file is
missing). A second run reports `total changes: 0`.

## Revert

See the README row: disable the path unit, delete the kitty files and units,
remove the `kitty-clear` block (or restore the rc backup), delete the user
`system_actions` key and the two mimeapps lines, `sudo apt-get purge kitty`.

## Verification

```bash
./install.sh --only kitty --dry-run
./install.sh --only kitty                # then again: "total changes: 0"
systemctl --user is-enabled kitty-cosmic-colors.path
grep -c 'alias clear' ~/.zshrc           # 1, inside the block
cat ~/.config/kitty/cosmic-colors.conf   # selection_background #rrggbb
tests/test-kitty.sh tests/test-login-rc.sh
```
